# i18n rules (WordPress theme)

## Text domain

**`studioval-boilerplate`** — the single source text-domain. Every translation call and every `block.json` `textdomain` field uses this exact value. `bin/setup.sh` substitutes the `boilerplate` token with the client project slug on install.

No aliases. phpcs (`WordPress.WP.I18n.TextDomainMismatch`) enforces it via `phpcs.xml.dist`.

## Translation function cheat sheet

| Goal                                           | Function                                      |
|------------------------------------------------|-----------------------------------------------|
| Return a translated string                     | `__( 'text', 'studioval-boilerplate' )`       |
| Echo a translated string                       | `_e( 'text', 'studioval-boilerplate' )`       |
| Return + escape for HTML                       | `esc_html__( 'text', 'studioval-boilerplate' )` |
| Return + escape for an attribute               | `esc_attr__( 'text', 'studioval-boilerplate' )` |
| Echo + escape for HTML                         | `esc_html_e( 'text', 'studioval-boilerplate' )` |
| Disambiguate identical strings in context      | `_x( 'Home', 'menu item', 'studioval-boilerplate' )` |
| Plural-aware                                   | `_n( 'one', 'many', $count, 'studioval-boilerplate' )` |
| Sprintf placeholders                           | `sprintf( __( 'Hello %s', 'studioval-boilerplate' ), $name )` |

**Prefer `esc_html__` / `esc_attr__` / `esc_html_e` over the bare versions** when the result is going straight to output — it covers escaping and translation in one call.

## Patterns

Block patterns live under `wp-content/themes/theme-fse/patterns/{slug}.php`. Every user-visible string inside pattern markup is wrapped in `esc_html_x()` with the translator context set to `'Pattern placeholder'` so translators know the strings are demo content.

## Generating the `.pot`

```bash
ddev wp i18n make-pot wp-content/themes/theme-fse \
    wp-content/themes/theme-fse/languages/studioval-boilerplate.pot
```

Regenerate before every release. The stub file at `languages/studioval-boilerplate.pot` has the correct headers; make-pot overwrites the content while preserving them.

## What gets extracted

WP-CLI's `i18n make-pot` scans:

- All `__()`, `_e()`, `_x()`, `_n()`, `_ex()`, `_nx()`, and their `esc_*` variants.
- `block.json` `title`, `description`, `keywords`, and `styles[*].label` fields — provided `textdomain` is set on the block.
- Pattern header fields (`Title`, `Description`, etc.).
- `style.css` header strings.
